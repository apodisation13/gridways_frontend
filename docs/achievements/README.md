# Достижения / контракты Gridways

Сверено с локальным кодом фронта и бэка 2026-11-13. Это память о текущей реализации, не история всех предложений в чате. Примеры не устанавливают конфиги в БД и не являются выгрузкой действующего каталога.

## С чего начать

- Новые задания или категории: [configs.md](configs.md), [config-examples.json](config-examples.json).
- Новый механизм, синхронизация, прогресс, награды: [architecture.md](architecture.md).
- Новое событие или место вызова: [events.md](events.md).
- Повторяемый рабочий процесс: [проектный скилл](../../.agents/skills/gridways-achievements/SKILL.md).

## Что реализовано

Убийства врагов и снятие щита/брони: события с полным снимком врага и режимом; count фактов и sum снятых единиц брони. См. категорию enemies в примерах и карту вызовов в events.md.

Постоянные достижения: `count`, `sum`, `unique`, `current`, `streak`; AND-фильтры по вложенным полям; события карт/лидеров и их пассивок с режимом, победы/поражения в боях, ресурсов, крафта/разбора, покупки прокачек и проверки текущего баланса/прокачек. Подтверждение и выдача награды на бэке. На фронте предварительный прогресс, очередь, фильтры, закрепление до 5 контрактов, уведомления о наградах.

## Что не завершено

- Daily/weekly: структура типов, вкладки и таблица `achievement_sets` есть, но выдача выбранных наборов, задачи выбора, сбросы и подсчёт периодов ещё не реализованы. План: общий для всех набор (например, 3 daily), выбираемый серверной задачей в полночь. Часовой пояс и граничные события периода нужно определить при реализации.
- Max за историю, отдельные универсальные счётчики внутри матча/хода и произвольные OR-группы — только обсуждались. Не выдавать их за поддерживаемые конфиги.
- Расходы ресурсов на прокачки арены пока не подключены; сами покупки, использование и восстановление аренного инвентаря уже учитываются.
- Доход от оплаченных покупок (`PaymentResultPage`) намеренно отложен. Загрузка баланса через GET сама по себе не является событием заработка.
- Большая часть будущих игровых контрактов ещё не спроектирована; не считать эту документацию полным продуктовым планом.

## Основные файлы

Все пути фронта относительно корня этого репозитория:

| Назначение | Файлы |
|---|---|
| Типы / enum / конфиги / прогресс | `src/types/achievements.ts`, `src/types/upgrades.ts` |
| Общий вход, преобразование событий | `src/logic/achievements/trackAchievementEvent.ts` |
| Фильтры и предварительный подсчёт | `src/logic/achievements/filters.ts`, `processAchievementEvents.ts` |
| Проверки состояния | `currentResources.ts`, `currentUpgrades.ts`, `currentDecks.ts`, `deckSummary.ts`, `upgradeSnapshot.ts` в той же папке |
| Очередь и HTTP | `syncAchievementEvents.ts`, `src/store/modules/achievements.ts` |
| Награды как доход, тосты | `trackAchievementRewards.ts`, `achievementRewardToasts.ts` |
| Страница / карточки | `src/pages/AchievementsPage.vue`, `src/components/Pages/AchievementsPage/` |
| Подключение подписок | `src/main.ts` |

Бэк — отдельный репозиторий `GridwaysBackend`. Найти его checkout в текущем рабочем окружении или уточнить расположение у пользователя. Персональные абсолютные пути в документации не сохраняем. В нём:

- `services/api/app/apps/user_achievements/{schemas.py,routes.py,service.py}`;
- `.../logic/{events.py,filters.py,upgrades.py,decks.py,user_achievements.py}`;
- `services/api/app/apps/progress/service.py` — загрузка прогресса;
- `services/api/app/apps/game_data/logic/game_const.py` — выдача констант;
- `lib/utils/models/game/achievements.py` и миграция `2026_11_09_1752_b2d646105a26_achievements.py`;
- `lib/utils/schemas/game.py` — ResourceType, UpgradeType, UpgradeSubtype, исходные конфиги.

## Возобновление в новом диалоге

Например: «Используй $gridways-achievements. Добавим контракт …». Указатель в корневом `AGENTS.md` позволяет найти документацию и без явного имени скилла. Проектное расположение `.agents/skills/` соответствует [официальной инструкции](https://developers.openai.com/api/reference/cli#use-the-cli-from-a-coding-agent); обнаружение нового скилла проверять в новой сессии. Если интерфейс не показывает скилл, можно явно попросить прочитать его файл.

После изменения механик обновлять соответствующий документ и примеры. Перед изменениями сверять код: сохранённая документация может отстать от него.
