# Создание и проверка конфигов

`config-examples.json` — компактный справочник механизмов, не полный каталог игровых заданий. Оставляем разные события, счётчики и условия; новые цели, цвета и режимы сами по себе не требуют ещё одного примера. Единственная повторяющаяся пара kill_enemies_50/250 показывает group.

Покрытие: count/sum/unique/current/streak; литералы строк, чисел, bool и null; eq/ne/gt/gte/lt/lte/in/exists; вложенные пути и AND; reset-массив с одним или несколькими условиями; фактический результат предмета; стоимость/выручка; снимки состава при сохранении и победе.

## Контракты врагов

В примерах оставлены две серии убийств: Bronze со сбросом при другом цвете или лидере и урон > 20 со сбросом при уроне <= 20 у обычного врага. Другие режимы и посторонние события не влияют на серию. Начало/конец боя её не сбрасывают. Полные серии непересекающиеся; уже выполненные серии при сбросе сохраняются.

Категория `enemies` демонстрирует убийства, наличие deathwish, снятие защиты, серии и состав кладбища при победе. Обычные враги определяются через enemy.color exists true; лидеры — false. Дополнительные поля врага фильтруются тем же механизмом.

Снятие брони бывает двух видов: enemy.armor_removed с count (раз на одного врага) или sum по amount (единицы брони). Одна способность, снявшая 5 брони с одного врага, даёт +1 либо +5 соответственно. Щит — enemy.shield_removed/count. Повторяющимся целям назначены группы отображения. Награды демонстрационные; старые конфиги менять не требуется. БД автоматически не обновляется.

[config-examples.json](config-examples.json) — валидный JSON с корнем achievements (`permanent`), демонстрационные значения и награды. Не импортировать весь файл поверх живого каталога. Из него копируют нужные категории/задания, проверив баланс и наличие ресурсов/фракций.

## Вложенность

```text
game_const.achievements.permanent
  title
  categories
    <category_id>
      id, title, ordering
      achievements
        <achievement_id>
          id, title, ordering, event, filters, counter, target, rewards
```

Категория вставляется в `categories`, задание — в её `achievements`. Не вставлять категорию вторично внутрь achievements: у такой «карточки» нет rewards, UI упадёт на definition.rewards.resources. Ключ задания совпадает с id, ID уникален между категориями секции. При смене смысла уже выданного контракта использовать новый ID, иначе унаследуется прежний прогресс/награда.

## Фильтры

Все поля соединены AND. Путь относительно data (`actor.color`, `recipe.rare_gem`, `spent.money`). Литерал — строгое равенство. Операторы:

| type | value |
|---|---|
| eq / ne | строка, число, bool или null |
| gt / gte / lt / lte | конечное число |
| in | список скаляров; OR только среди значений одного поля |
| exists | bool; проверка присутствия поля, null тоже присутствует |

Отсутствующее поле не проходит даже ne; для отсутствия нужен exists:false. Число и строка не приводятся друг к другу. Произвольных групп OR нет. Путь может содержать индекс массива; `__proto__`, `prototype`, `constructor` запрещены.

Пример: actor.color = Bronze И actor.data.damage >= 8. Для Monsters ИЛИ Animals достаточно одного `in`. Проверка actor.passive_ability.name ne null означает существующее ненулевое поле.

## Счётчики

- count: target — число событий, counter без field.
- sum: field содержит положительное количество. Крафт/покупка ресурса обычно sum amount; стоимость покупки — sum spent.money, выручка — sum gained.money.
- unique: field — строковое название/числовой ID. Для «все девять предметов» ограничить resource через in девятью значениями и target 9. Не переводить «30 разных» в 30 обычных событий.
- current: event только resources.checked, upgrades.checked или decks.checked (field decks.count). Поля ресурсов — resources.<resource>. Поля прокачек описаны в [events.md](events.md). Для all_maxed target 1, для уровня/эффекта — нужный порог. Остальные события не допускают current.

Уникальность по фракции требует проверить, что каждая фракция имеет доступного для нужного действия лидера/карту. Наличие Neutral в UI-списке фракций не доказывает, что нейтрального лидера можно скрафтить. Не обещать достижимость только по enum.

## Награды и сортировка

`rewards: {resources: {money: 100}}`; нулевые/положительные целые количества. Карты/лидеры в rewards пока не реализованы. Категории и задания имеют независимый ordering; выполненные в UI сортируются по времени подтверждения. Конфиги примеров не назначают реальную экономику игры.

## Проверка перед применением

Из корня фронта:

```sh
python3 docs/achievements/validate_catalog.py docs/achievements/config-examples.json
```

Это офлайн-проверка структуры, ID, типов событий, счётчиков и языка фильтров, без доступа к БД и без запуска backend tests. Она не доказывает достижимость target, наличие игрового объекта или правильность экономики. Поддерживаемые события/enum берутся из исходного TypeScript; при новом механизме обновить и код валидатора. Для новых runtime-механик отдельно проверить совпадение логики фронта/бэка и необходимые type/lint проверки.

Перед импортом проверить реальный game_const и ресурсные имена. Не заменять пользовательский каталог примерами, не выполнять SQL-изменения без поручения на изменение БД.

### Колоды

`deck.created` и `deck.deleted` используют count; фракция доступна как `deck.leader.faction`. `decks.checked` использует только current с field `decks.count`: число хранящихся колод, включая базовую. Порог 3/5/7/10 задаётся target; примеры приведены в категории decks файла config-examples.json. Редактирование не является новым созданием.

Для состава используйте deck.saved с count и target 1: фильтры deck.summary.all_bronze/all_silver/all_gold/no_neutral/all_neutral = true или deck.summary.cards_count = 20. Условия можно сочетать через обычное AND. Событие работает при создании и редактировании, но не при загрузке. В категории decks оставлены примеры одноцветного состава и размера колоды; остальные варианты отличаются только полем фильтра.

### Контракты по режимам

mode = normal/random_n/random/multiplayer/arena. Для action.played добавьте mode и actor.color exists true, если лидер не должен учитываться. Пример Monsters: дополнительно actor.faction = Monsters. game.won использует count и mode выбранного режима. Начало игры не является событием достижений. Для random, multiplayer и arena меняется только mode; дублировать весь набор не нужно.

[normal-mode-card-contracts.sql](normal-mode-card-contracts.sql) добавляет mode:normal только permanent action.played без явно заданного mode. Скрипт необходимо применить отдельно; сами изменения кода не ограничивают ранее сохранённые конфиги. Накопленный прогресс сохраняется: прошлые события других режимов из него не вычитаются.

### Арена

В категории arena оставлены примеры покупки прокачки, восстановления предмета, достижения уровня и победы без золотых карт. Уровень достигнут сразу после победы на предыдущем; остальные режимы/пороги задаются теми же полями.

Старые resource.spent-контракты инвентаря оставляются без изменений. inventory.used на добор карт теперь работает и в арене; чтобы сохранить прежний охват, добавить filters.mode = {"type":"ne","value":"arena"}. Для только обычного режима вместо этого использовать "normal".

### Обычная игра

Категория normal: game.won + filters.mode = normal. Фракция определяется фильтром starting_deck.leader.faction, сложность — difficulty = easy/normal/hard. Для состава используются starting_deck.summary.all_bronze/all_silver/all_gold, для победы без лидера — leader_uses = 0. Все счётчики count; повторное прохождение засчитывается. Примеры в config-examples.json, старые конфиги менять не требуется.

### Скрытые серии

В категории `enemies` оставлены `win_enemy_grave_total_30_5` и `win_enemy_grave_gold_20_5`: по 5 побед с минимумом 30 врагов или 20 золотых в текущем кладбище. Используют game.won, count и enemy_grave.total/gold >= N. Другие пороги меняются в конфиге.

`counter.reset` всегда непустой массив объектов `{event, filters}`. Сброс происходит при совпадении любого элемента. Старый одиночный объект необходимо вручную обернуть в массив в БД; совместимости со старым форматом нет. В примере серии убийств Bronze убийство лидера тоже сбрасывает текущую цепочку: уже добавлено вторым элементом `{ "event": "enemy.killed", "filters": { "mode": "normal", "enemy.color": { "type": "exists", "value": false } } }`.

В normal оставлен normal_win_streak_3_5 (length 3, target 5). Для одной серии из 10 побед достаточно length 10, target 1. Основной event game.won с mode normal; reset event game.lost с mode normal. Подходящая победа продвигает скрытый streak, поражение обнуляет только его, каждая полная серия увеличивает value. Серии непересекающиеся; неподходящие события не сбрасывают их. UI отображает только value/target. Существующие контракты менять не нужно.

### Пассивные способности

Категория passives содержит по одному примеру карты в руке, лидера и passive_once. Для карты: actor.color exists true + location hand/deck/grave. Для лидера: actor.color exists false (в игровом обработчике location hand). Примеры ограничены mode normal. Дополнительные фильтры actor.color/actor.data.damage/actor.passive_ability.name работают без новых счётчиков. Существующие контракты менять не нужно. Активация при таймере учитывается после запуска поддерживаемого обработчика; условные реакции и начало боя — только при подтверждении boolean от способности.

Для пассивок начала боя: event passive.triggered, filters.location = passive_once. Пример passive_once_10 лежит в категории passives и ограничены mode normal. Для обычных пассивок колоды остаётся location deck; начало боя больше в этот фильтр не попадает.

### Группы карточек

Необязательное group: непустая строка, например "gain_money". Внутри одной категории невыполненные задания с одинаковым group сворачиваются в одну строку со стрелками. Без group задание остаётся одиночным. Группа влияет только на UI, все задания считаются независимо по id. Выполненные по датам бэка всегда отдельные, локальное достижение target не считается завершением.

Внутри группы сортировка target, ordering, id; по умолчанию ближайшая оставшаяся цель. В списке строк невыполненные идут первыми по минимальному ordering строки, выполненные — по времени завершения от нового. При подтверждении показанного задания переключаемся на ближайшее оставшееся. Позиция живёт только в компоненте страницы, перезагрузка её сбрасывает. Фильтры применяются до группировки, включая pinned; закрепляется только показанное задание, не вся группа. Счётчик категории отражает количество всех заданий, а не свёрнутых строк.

Добавлять group в БД можно вручную; отсутствие поля полностью поддерживается. В подсчёте, наградах и пользовательском JSONB-прогрессе изменений нет.
